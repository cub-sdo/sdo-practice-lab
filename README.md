# SDO Practice Lab

Exam practice for **Software Development & Operation** (Constructor University, Fall 2026).
133 questions from the lectures, tutorials and group presentations of weeks 1–6, with an
explanation and a source slide for every answer.

> Unofficial practice tool maintained by the course TA. Results are not graded.

## What students can do

- **Practice** by week or by topic, with the answer and explanation after every question.
- **Exam simulation**: 10, 20 or 30 mixed questions from every topic, one minute each, results at the end against the 45 % pass mark.
- **Re-run failed**: repeat exactly the questions they got wrong last time.
- **Coverage by topic**: see which topics they have not practised yet.

Four question types:

| Type | Example |
|---|---|
| `single` | Which instruction defines what runs when the container starts? |
| `truefalse` | `git reset` is safe on shared branches, but `git revert` is not. |
| `order` | Put the Task 1 Dockerfile lines in order. |
| `input` | Type the command that builds an image tagged `converter`. |

## Privacy

The site is fully static. There is no login, no analytics and no request to any third-party
server (the IBM Plex fonts are self-hosted). Progress is stored only in the student's own
browser (`localStorage`) and can be deleted with **Reset my progress**.

## Project layout

```
questions/            the question bank (one JSON file per week) + topics.json
scripts/build.py      validates the questions and bundles them into site/questions.js
site/                 the static website (index.html, style.css, app.js, fonts/)
.github/workflows/    CI/CD: validate on every pull request, deploy to GitHub Pages from main
```

`site/questions.js` is generated by the build and is not committed.

## Run it locally

Needs only Python 3 (standard library).

```bash
python3 scripts/build.py          # validate + write site/questions.js
python3 -m http.server -d site    # open http://localhost:8000
```

Opening `site/index.html` directly in the browser also works after the build.

## Deploy (one-time setup)

1. Push this repository to GitHub (e.g. `uhuseynov/sdo-practice-lab`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Push to `main`. The workflow validates the questions, builds the site and deploys it.
   The URL appears in the run summary (usually `https://<user>.github.io/sdo-practice-lab/`).

If the repository name or owner is different, update the GitHub link in `site/index.html`.

## Add questions

See [CONTRIBUTING.md](CONTRIBUTING.md). In short: edit `questions/week-XX.json`, run
`python3 scripts/build.py --check`, open a pull request. The CI check fails with a clear
message if a question is incomplete, so a broken question never reaches the live site.
