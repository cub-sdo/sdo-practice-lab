# SDO Practice Lab

Exam practice for **Software Development & Operation** (Constructor University, Fall 2026).
133 questions from the lectures, tutorials and group presentations of weeks 1–6, with an
explanation and a source slide for every answer.

> Unofficial practice tool maintained by the course TA. Results are not graded.

## What students can do

- **Practice** by week or by topic, with the answer and explanation after every question.
- **Exam simulation**: 10, 20 or 30 mixed questions from every topic, one minute each, results at the end against the 45 % pass mark.
- **Re-run failed**: repeat exactly the questions they got wrong last time.
- **Coverage by topic**: see which topics they have not practised yet.

Four question types:

| Type | Example |
|---|---|
| `single` | Which instruction defines what runs when the container starts? |
| `truefalse` | `git reset` is safe on shared branches, but `git revert` is not. |
| `order` | Put the Task 1 Dockerfile lines in order. |
| `input` | Type the command that builds an image tagged `converter`. |

## Privacy

The site is static. There is no login for students and no request to third-party servers
(the IBM Plex fonts are self-hosted).

- **Personal progress** (what a student answered, what to re-run) stays in the student's own
  browser (`localStorage`) and can be deleted with **Reset my progress**.
- **Anonymous class statistics** are optional and only active when `site/config.js` names a
  Supabase project. For each answer the site sends the question id, right/wrong, the chosen
  answer, practice or exam, a random id for that run and the time. No name, no student ID, no
  device identifier. The footer tells students this and lets them turn it off.

## Project layout

```
questions/            the question bank (one JSON file per week) + topics.json
scripts/build.py      validates the questions and bundles them into site/questions.js
site/                 the static website: practice app (index.html, app.js),
                      TA dashboard (stats.html, stats.js), config.js, style.css, fonts/
supabase/schema.sql   database for the anonymous class statistics (table, rules, summary function)
supabase/tests/       CI test that checks who can read and write what
.github/workflows/    CI/CD: validate questions + test database rules on every pull request,
                      deploy to GitHub Pages from main
```

`site/questions.js` is generated by the build and is not committed.

## Run it locally

Needs only Python 3 (standard library).

```bash
python3 scripts/build.py          # validate + write site/questions.js
python3 -m http.server -d site    # open http://localhost:8000
```

Opening `site/index.html` directly in the browser also works after the build.

## Deploy (one-time setup)

1. Push this repository to GitHub (e.g. `uhuseynov/sdo-practice-lab`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Push to `main`. The workflow validates the questions, builds the site and deploys it.
   The URL appears in the run summary (usually `https://<user>.github.io/sdo-practice-lab/`).

If the repository name or owner is different, update the GitHub link in `site/index.html`.

## Class statistics (optional, about 15 minutes)

Without this step the site sends nothing anywhere. With it, you get a TA dashboard at
`/stats.html`: answers per day, accuracy per topic, the hardest questions and the most common
wrong answer for each.

1. Create a free project on [supabase.com](https://supabase.com). Region: **Central EU (Frankfurt)**.
2. **SQL Editor → New query**, paste the whole `supabase/schema.sql`, **Run**.
3. **Authentication → Sign In / Providers**: turn off new user sign-ups, so nobody else can create an account.
4. **Authentication → Users → Add user**: your email and a strong password (auto-confirm the user).
5. Make that account a TA. In the SQL Editor:
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'your.email@example.com'
   on conflict do nothing;
   ```
6. **Project Settings → API Keys**: copy the project URL and the **publishable** key into
   `site/config.js`, commit and push. Never put the secret or `service_role` key in the site.
7. Open `https://<user>.github.io/sdo-practice-lab/stats.html` and sign in.

Good to know:

- The database rules let visitors only **add** answers. Reading needs a signed-in account that is
  listed in `public.admins`. CI checks these rules on every pull request (`supabase/tests/`).
- Anyone can send fake answers, because students do not sign in. Treat the numbers as a signal
  for the tutorial, not as grades.
- Free Supabase projects pause after a week without activity; restore them from the dashboard.
- Delete the data when the course ends (SQL Editor): `truncate public.attempts;`

## Add questions

See [CONTRIBUTING.md](CONTRIBUTING.md). In short: edit `questions/week-XX.json`, run
`python3 scripts/build.py --check`, open a pull request. The CI check fails with a clear
message if a question is incomplete, so a broken question never reaches the live site.
